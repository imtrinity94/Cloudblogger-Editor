Fake inventory used by VcPlugin, Server, RESTHost and mocked actions. Edit the JSON; it applies on the next run.

This is not an emulator. Your script runs on the actual Mozilla Rhino builds that Orchestrator ships: 1.7R4 for 8.x and 1.7.15 for 9.x, compiled from the official release tags and executed in a WebAssembly JVM (CheerpJ) inside your browser. Nothing is sent to a server.

Orchestrator's own restrictions are applied on top:

  • Language level: JavaScript 1.7 on 8.x, ES6 mode on 9.x — so syntax support is decided by the real parser.
  • Class shutter: only java.util.* is reachable from scripts, the vRO default.
  • Actions are wrapped in a function (return works); scriptable tasks run outside the root scope (return is a syntax error).
  • 9.x enables Java Map property access (map.key) and a console object; 8.x has neither.
  • Error messages and line numbers come straight from Rhino, labelled like Orchestrator does.

What is mocked: System, Server, VcPlugin and VC objects, RESTHost/RESTHostManager, Properties, LockingSystem, File, MimeAttachment and mocked actions via System.getModule. They read the editable inventory in the Mocks tab and never touch real infrastructure.
